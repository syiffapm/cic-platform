1. Summary

The frontend is one codebase with five portal areas, each loaded as its own bundle. Menus, routes and buttons follow the role-based permission matrix; every screen is available in English and Myanmar. The reference build keeps data in the browser — in production each page calls the backend engines listed next to it.

2. Technology & standards

FrameworkReact 18 + Vite 5, React Router 6 (one lazy-loaded bundle per portal)
StylingTailwind CSS 3 with design tokens (navy primary, amber accent, teal), Poppins + Noto Sans Myanmar (self-hosted)
Charts & mapsRecharts; Leaflet + TopoJSON boundaries (330 townships, 15 states/regions)
LanguagesEnglish and Myanmar (Unicode) on every screen; translation dictionary served from the CMS
AccessibilityWCAG 2.1 AA — 0 serious axe violations, no horizontal scroll at 390 px, keyboard and screen-reader support
Security in the UIRole-based menus, routes and buttons from the permission matrix; masked personal data by role; session info in the header
HostingStatic SPA (currently Vercel); in production served behind the API gateway / CDN

3. Shared frontend foundation

Design system (UI kit)Button, Card, Badge, StatCard (KPI with definition + as-of), DataTable (sort, search, paging; cards on phones), Modal, Form fields, Tabs, Alert, Toast, Timeline, Stepper, MakerCheckerBanner, ChartCard, EmptyState
LayoutsPublic header/footer with accessibility toolbar and language switch; portal shell with collapsible, searchable sidebar (/ or Ctrl+K), notifications, "Your access" popover, session info
Authentication screensCitizen sign-in (/login) with first-sign-in and SMS code steps; Staff Workspace sign-in (/workspace/login) with authenticator step; auth guards per portal
Permission layerusePermissions(portal).can(feature, action) driving sidebar items, route guards (access-denied screen + audit) and every create / update / delete / approve / export control
Localisation layerRuntime translator for all rendered text and attributes, Myanmar typography rules, browser-language default, EN/MM switch
State & data accessStore and auth contexts today (browser storage); replaced by API clients per backend engine in production
Common patternsConfirmation dialogs with reason for irreversible actions, work queues ("Needs your action" / "My work"), SLA badges, empty and error states, print/PDF views with QR
